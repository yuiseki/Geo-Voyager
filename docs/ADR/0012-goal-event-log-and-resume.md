# 0012 Goal の出来事の記録を正本にし、途中から再開する

2026-10-14。

## 背景

- 1 つの Goal には 20〜35 分かかる。Goal の途中の記録（`GoalHistory`）はメモリの中にしかなく、trace.json、exploration.jsonl、world.jsonl は、どれも Goal が終わってから実行結果（`AdaptiveGoalExecution`）から書いていた。
- 途中でモデルの呼び出しが時間切れになったり、プロセスが止まったりすると、その Goal の手はすべて失われた。
- 出来事の型は、すでに `goal_history.py` の 3 つ（手、計画の失敗、最終判定の失敗）にまとまっている。並び順どおりの一覧（`events`）もある。打ち切りの回数（計画の失敗の回数など）も、履歴から数えている。

## 決定

1. Goal ごとに `NNN/events.jsonl` を作る。中身は次の 3 種類で、出来事が起きるたびに 1 行ずつ追記する（`geo_voyager/event_log.py`）。
   - 始まり: Goal の文、渡した記憶の文面、curriculum が挙げた理由
   - 出来事: 手、計画の失敗、最終判定の失敗
   - 終わり: 止まり方と、答えが出たか。Critic の文は書かない（[0011](0011-exploration-graph-checked-failures.md)）
2. 出来事は、JSON に書き出して読み戻すと元と等しくなる。手の記録には、その手で試したコードの数（`attempts`）も持たせる。trace はこれを読むので、実行の詳細（`IntentExecution`）がメモリに無くてもよい。
3. 実行ループ（`execute_adaptive`）は、読み戻した出来事（`events=`）から始められる。打ち切りの回数は、それも数える。
4. `bench/run_explore.py --resume` は、終わりの行が無い Goal を、その次の手から再開する。Goal が例外で壊れたとき（モデルの呼び出しの時間切れ、SIGTERM）は、終わりの行を書かない。モデルの呼び出しの保存の番号は、既にある保存の続きから振る。`--replay` で同じ出力先に流し直すと、始めた Goal の続きから流す。
5. trace.json、exploration.jsonl の行、world.jsonl の発見は、ログを読み戻したもの（`LoggedGoal`）から作る。`LoggedGoal` は、実行結果と同じ欄（`goal`、`events`、`history`、`stop_reason`）を持つ。World Graph は、最終判定の Critique ではなく止まり方を見る（止まり方が done になるのは、最終判定が成功したときだけ）。

## 確かめたこと

- 決まった応答を返すモデルの代わりで Goal を第 3 手で止め、再開させた。第 3 手だけがもう一度実行され、出来事の並びと終わり方は、止めずに流した場合と一致した。実行結果から作った 3 つの記録と、ログだけから作った 3 つの記録も一致した。
- 本物の LLM で Goal 5 を第 2 手の後に SIGTERM で止め（終了コード 143、コンテナは片付いた）、`--resume` で再開した。第 3 手から続き、5 手で 14.541 km に届いた。止める直前の呼び出しと、再開して最初の呼び出しのプロンプトは同じだった。再開後の 10 回の呼び出しのプロンプトは、止めずに流した実行の対応する 10 回と、すべて一致した。

## 結果

- 止まった Goal を、失った手なしに続けられる。
- Goal の記録の正本は `events.jsonl` の 1 つになる。ほかの記録は、そこから作り直せる。
- 例外で壊れた Goal には、exploration.jsonl に error の行が書かれる。その後で再開すると、同じ番号の行がもう 1 つ増える。記憶（`memory`）は最後の行を読むので、再開した結果が使われる。SIGTERM で止まった Goal には、error の行は書かれない。
