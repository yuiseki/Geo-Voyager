# Critic が誤答を通した 11 件

2026-10-09。保存済みの測定（条件 A の `mix_a`、条件 B の `mix_b`、新方式の `identity_a`）で、semantic-completion に分類された 33 件のうち、全 step が実行に成功して Critic も通したのに Goal の答えが誤りだった 11 件を、記録を読んで分類した。追加の LLM 実行なしで分類した（Critic の再質問は後述）。

## 分類

| 型 | 件数 | 事例 | Observation の特徴 |
|---|---|---|---|
| 退化した値を通した | 6 | `tag_sushi_count` 3 件（count が 0）、`stations_count`（総数が 0）、`route_auto_km`（0 km）、`route_walk_minutes`（8.15 m で 99 分） | 数値が書かれていることを理由に成功にしている。値が 0、または値同士が矛盾する |
| 要求した値でなく一覧を返した | 4 | `sparql_ward_count` 2 件、`sparql_four_char_wards`（件数や 4 文字の数を求める Goal で、23 区の一覧だけを返した）、`library_setagaya`（件数を求める Goal で地物の一覧を返した） | Critic の理由が「一覧が取得されたため」「件数 23 が明示されているため」と、一覧の存在を理由にしている |
| Intent 自体が回答でない | 1 | `cafe_vs_restaurant_shibuya`（最後の Intent が「渋谷区」だけで、ID を返した） | Planner の誤り。Critic は Intent の文面に対して答えているので通した |

- 共通原因は、Critic プロンプトの「外部知識で答えを推測しない」「期待件数を仮定しない」が、0 や矛盾する値を疑う余地まで消していたことと、Critic が Goal を見ず Intent だけを見ていることである（後者は設計）。
- 型 2 と型 3 は、1 つの step で終わる旧方式の計画で起きた。観察駆動の適応ループでは、DONE のあとに Goal 全体を見る最終 Critic があり、この 2 つの型はそちらの領分である。今回は触れていない。
- 決定的な検査で防げるのは型 1 の一部（0 の単一の値）だが、0 が正しい Goal（例えば 0 件の地物）を誤って拒否する危険がある。今回のベンチマークの Goal は oracle がすべて非 0 なので、この誤拒否は測れない。決定的な検査は入れていない。

## 変更と確認

Critic プロンプトに、回答の値が 0 や空のとき、または値同士が矛盾するときは、その値が正しいと分かる根拠が Observation にあるときだけ成功にする、という指示を足した（単体テスト 745 件が通る）。

保存済みの最終 step を同じ Critic（thinking なし）に聞き直した（`bench/replay_critic.py`、`mix_a` と `identity_a` から対象 9 件、対照 25 件）。

| | 変更前 | 変更後 |
|---|---|---|
| 対象（誤答）を拒否した | 0 / 9 | 2 / 9 |
| 対照（正答の run の最終 step）を拒否した | 5 / 25 | 5 / 25（同じ 5 件） |

- 変更後に拒否したのは、矛盾（8.15 m と 99 分）と、0.0 km の 1 件。件数 0 の 3 件（寿司 2 件、駅数）は、変更後も通った（理由は「0 が報告されているため」）。
- 対照は、変更の前後で拒否が増えなかった。5 件の拒否は両方の測定で同じ run で、変更と無関係である（対照は最終 step だけを再生し、前段の文脈を省いているため、元の判定とは異なる可能性がある）。
- 再生は `mix_a` と `identity_a` だけを使い、`mix_b` は含めていない。対象 9 件のうち 7 件は上の 11 件に含まれ、2 件（`sparql_four_char_wards.r1`、`nom_setagaya_south.r2`）は 11 件の外で、同じ基準（全 step が通って答えが誤り）で選ばれた別の run である。件数が少なく、1 回の再生なので、効果の大きさは言えない。

## 結論

- 型 1 に対する Critic プロンプトの変更は、矛盾する値には効いたが、0 の件数には効いていない。0 の件数は、プロンプトでは防ぎ切れない。
- これ以上 Critic を深追いせず、適応ループの focused E2E（各 Goal 1 回）で、観察駆動の最終 Critic と `対象:` の制限の効果を見るのが次の一歩になる。
