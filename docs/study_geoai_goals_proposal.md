# study-geoai-algo-py の実験を Goal と oracle に変える案

2026-10-10。案だけで、コードはまだ書いていない。前提は [analysis_sandbox_design.md](analysis_sandbox_design.md)（分析用 sandbox の検討と決定）。

固定したデータそのものはリポジトリに入れない（ライセンスが CC BY-SA のみちよみなどを含むため）。リポジトリには、取得して固定するスクリプトと、版と出典の記録だけを置く。

Geo-Voyager は study-geoai-algo-py から独立させる。使うのは、study-geoai の各実験の README に書かれた問題設定（行、目的変数、特徴量、除外の条件、評価の方法）と結果の数字だけで、コードとキャッシュは使わない。データは Geo-Voyager が同じ出どころと版から自前で取得して固定する。

## 1. 選び方

38 実験から、次を満たすものを最初の候補にした。

- 問題設定が README の文章で決まる。文章だけでは決まらない定義（例えば 005-A の、Overture の POI の種類を名前の語で束ねる規則）を含む実験は外す。
- 台東区で動く（小さく速い。study-geoai でも主に台東区で回している）。
- 数字の oracle がある（係数、スコア、分散の割合、距離など）。図だけの結果は使わない。
- 系統が散らばる（分類、回帰、次元削減、経路）。

データの準備が軽い順に並べた。

| 順 | 実験 | 系統 | データ | 準備の重さ |
|---|---|---|---|---|
| G1 | 001-B ロジスティック回帰（無電柱化） | 分類、評価、目的変数の漏れ | みちよみの台東区のシーン（Parquet 1 ファイル） | 軽い（1 表、空間の結合なし） |
| G2 | 006-A PCA（250m 格子） | 次元削減、標準化、成分数の決め方 | みちよみの台東区のシーン | 軽い（格子ごとの集計だけ） |
| G3 | 001-A 線形回帰（人口密度） | 回帰、正則化 | 国勢調査の小地域、Overture の建物と POI | 中くらい（空間の結合） |
| G4 | 007-A Dijkstra（最寄りの病院と避難場所） | 経路、グラフの構築 | OSM の道（osm-tokyo23-src-2026-08）、国土数値情報 P04、tokyo-ckan の避難場所、小地域 | 重い（道路網の構築） |

外した主なもの: 005-A k-means（POI の種類の束ね方が文章で決まらない）、003 系（Ookla は非商用ライセンス。リポジトリに入れない方針）、004-D など AgERA5 を使うもの（取得に約 10 分）、008 以降の最適化（G4 の道路網が前提。G4 のあとに足す）。

## 2. 各 Goal の案

Goal の文には、問題設定（データ、行、目的変数、特徴量、除外、評価）と、答えに含める項目を書く。設定を書かない自由な Goal（「無電柱化を予測するモデルを作って」）は、答えが一意に決まらず oracle と比べられないので、後の段階にする。

### G1 001-B: 無電柱化の分類と、目的変数の漏れ

- Goal の文（案）: 「みちよみの台東区の街路シーンで、無電柱化済か架空線ありかを、道と見た目の特徴量（車道の幅、左右の歩道の有無、緑の割合、色の鮮やかさ、道路照明の数）からロジスティック回帰で分類する。不明と、特徴量の空の行と、隔離されたシーンは除く。特徴量は標準化する。無電柱化済の割合、すべて架空線ありと答えたときの精度、ランダムな 5 分割の AUC と精度を求める。次に、見える電柱の数と電線の密度が高いかを特徴量に足した AUC を求め、それが予測に使えるかを答える。」
- データ: みちよみ（`finalvent/michiyomi-tokyo-streetscape`、台東区の scenes）。study-geoai が使った版（キャッシュ名のリビジョンは `e4966cdceff6` で始まる）に合わせる。
- oracle（study-geoai の README）: 使った行 32,593（53,948 シーンのうち）、無電柱化済の割合 11.6%、すべて架空線ありの精度 0.884、AUC 0.849、精度 0.905、電柱と電線を足した AUC 0.988。台東区の係数（標準化した特徴量あたり）: 道路照明 -0.999、緑 +0.674、車道の幅 -0.421、色 +0.144、左の歩道 -0.036、右の歩道 -0.009。
- 許容誤差の案: 行数と割合は一致、AUC と精度は ±0.01（5 分割の乱数で動く）、係数は ±0.02。
- 試すこと: `analysis` の JSON 文字列から値を取り出す、除外の条件、標準化、交差検証、偏ったデータで精度より AUC を見ること、電柱の数が答えの言い換え（漏れ）だと答えられるか。
- 未確定: みちよみの資料（study-geoai の `docs/datasets/michiyomi/`）では台東区は 55,044 行、001-B は 53,948 シーン。版か除外の違いと思われる。「隔離されたシーン」の列と、「電線の密度が高い」の値の表し方は、データを開いて確かめる。

### G2 006-A: 道の特徴を PCA で 2 つの軸に縮める

- Goal の文（案）: 「みちよみの台東区のシーンを 250m 格子（`cell_250m`）ごとに平均した 12 個の数値（車道の幅、歩道の幅、歩道のある割合、電柱の数、街灯の数、緑の割合、色の鮮やかさ、無電柱化の割合、電線の多い割合、ブロック舗装の割合、見通しの悪い割合、撮影の枚数）で PCA を行う。割合は不明と該当なしを除いて数える。撮影が 30 枚未満の格子は除く。標準化した PCA の説明する分散の割合を第 4 主成分まで、標準化しない PCA の第 1 主成分の説明する分散の割合を求め、残す主成分の数を並行分析（各列を独立にシャッフルして 200 回、固有値の 95 パーセンタイルと比べる）で決める。」
- oracle: 格子 173、標準化した PCA の割合 0.409、0.207、0.108、0.074（2 つで 62%、4 つで 80%）、固有値 4.93、2.50、1.31、0.89、0.70、シャッフルの 95 パーセンタイル 1.57、1.40、1.31、1.22、1.13、残す数 2、標準化しない PC1 はほぼ 100%。
- 許容誤差の案: 格子数は一致、割合と固有値は ±0.01、シャッフルの値は ±0.05（乱数）、残す数は一致。
- 試すこと: 格子ごとの集計、割合の分母の扱い、標準化の要否、成分数の決め方。
- 未確定: 12 個の数値のそれぞれが `analysis` のどのキーか（車道の幅は `geometry.roadway_width_m.value` など一部は資料にある）、「ブロック舗装」「見通しの悪い」の値の表し方。G1 と同じデータを開いて確かめる。

### G3 001-A: 町丁目の人口密度を建物と POI から回帰する

- Goal の文（案）: 「台東区の国勢調査の小地域（町丁目）ごとに、中心が小地域の中にある Overture の建物の足元の面積を小地域の面積で割った値（coverage）と、log(1 + Overture の POI の数 / km²) を特徴量にし、log(1 + 人口密度) を線形回帰で当てはめる。特徴量は標準化する。学習の R²、ランダムな 5 分割の R²、標準化した係数、Ridge と Lasso の係数を求める。」
- データ: e-Stat の小地域境界と人口（`yuiseki/estat-boundary-2020`、Tokyo の r2ka13.parquet。キーは PREF + CITY + S_AREA の 11 桁で作り直す）、Overture Maps 2026-09-23.1 の建物と POI（台東区の範囲）。
- oracle: 小地域 108、学習の R² 0.364、5 分割の R² 0.284、係数 coverage +0.438、log_place_density -0.296、Ridge 0.419 / -0.281、Lasso 0.419 / -0.277。
- 許容誤差の案: 行数は一致、学習の R² と係数は ±0.01、5 分割の R² は ±0.03。
- 試すこと: 空間の結合（中心が面の中か）、面積の計算の座標系、対数変換、正則化。
- 未確定: 「108」が、人口 0 の小地域や面積の扱いでどう決まったか（README に 23 区で 0 人の小地域を 78 除いた話はあるが、台東区の除外の条件は明記が無い）。POI の数え方（Overture の places の全件か、確からしさで絞ったか）。再現できなければ、許容誤差を広げるか外す。

### G4 007-A: 町丁目から最寄りの病院と避難場所まで歩く距離

- Goal の文（案）: 「OSM の歩ける道から歩行者の道路網を作り、台東区の住む人のいる町丁目の中心から、最寄りの病院と指定緊急避難場所までの歩く距離を求める。中央値、90 パーセンタイル、最大、1km より遠い人口の割合を答える。」道路網の作り方（範囲に約 1km を足す、歩ける道の条件、頂点の座標を 1mm に丸めてつなぐ、最大の連結成分に寄せる、中心から道路網までの一歩を足す）も Goal の文に書く。
- データ: osm-tokyo23-src-2026-08 の line 表、国土数値情報 P04（2020 年、病院 `P04_001 = 1`）、tokyo-ckan の台東区の指定緊急避難場所（17 か所）、小地域。
- oracle: 病院 44 か所、中央値 645m、90 パーセンタイル 964m、最大 1,106m、1km より遠い人口 6.0%。避難場所 17 か所、434m、670m、1,057m、1.0%。道路網のノード 97,702、最大の連結成分 99.0%。
- 許容誤差の案: 行き先の数は一致、距離は ±1%、割合は ±0.5 ポイント。
- 試すこと: グラフの構築、多始点の Dijkstra、最近傍への寄せ、大きめの計算（study-geoai で 20 秒、418MB）。
- 未確定: 「歩ける道」の条件の細部（README の記述で足りるか）。国土数値情報の zip の取得（ライセンス上、Geo-Voyager のデータとして固定してよいかを確かめる。P04 は CC BY 4.0 と study-geoai の資料にある）。

## 3. oracle の確かめ方と、Goal の判定

1. Geo-Voyager に各 Goal のデータを固定するスクリプトと、参照解（Claude Code が書く分析のコード）を置く。参照解を分析の sandbox で動かし、上の oracle が許容誤差の中で出ることを確かめる。出ない数字は oracle から外す（理由を記録する）。
2. ローカル LLM の答えは、Goal の文で答えに含める項目を決め、judge が項目ごとに数字を比べる。出力のキーの名前を Goal の文で指定するか（判定が簡単）、名前を指定せず judge が意味で探すか（LLM の自由度が高い）は、決めていない。最初は指定する方が、詰まる場所が分かりやすい。
3. 答えの正しさとは別に、方法の正しさ（G1 で漏れを指摘できたか、G2 で標準化したか）も記録する。数字が合えば方法も合っていることが多いが、漏れの指摘のような判断は、数字だけでは見えない。

## 4. 進める順番の案

1. 分析用 sandbox（イメージ、資源の枠、データのマウント、成果物）を作る。
2. G1 のデータの固定と参照解。oracle が再現できることを確かめる。
3. G1 をローカル LLM で流す。どこで詰まるかを見る（実行環境か、データの読み方か、分析の組み立てか、判定か）。
4. G2、G3、G4 を同じ手順で足す。

G1 から始めるのは、データが 1 表で空間の結合が無く、データの準備の失敗と LLM の失敗を切り分けやすいからである。
